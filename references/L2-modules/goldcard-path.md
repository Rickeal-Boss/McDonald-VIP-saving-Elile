# L2 · 路径 A（麦金卡权益）

> 目标：判定卡权益本单是否生效；不生效时能否"改单激活"。

## 输入 / 产出
- 输入：菜单（`stage_s2_meals.json`）、时段、门槛、门店。
- 产出：`stage_s3_goldcard.json`（逐条权益 `{available, reason}`，含"本单无卡专属优惠"显式结论）。

## 卡权益清单（规则表 `goldcard_rules.py`）
| 权益 | 门槛 / 条件 | 触发维度 |
|---|---|---|
| 超值四件套 | 指定 SKU | 餐品匹配 |
| 6折自由搭 | 指定 SKU | 餐品匹配 |
| 早餐 6 折 | 时段 `05:00–10:29` | 时段 |
| 免配送费 | 满 19（早）/ 满 39（正餐） | 门槛 + 外送 |
| 满额福利金 | 到店满 39 / 麦乐送满 60 减 5 | 门槛 + 场景 |
| 9.9 麦咖啡 | 指定 SKU | 餐品匹配 |

## 判定依据（H2/H3 已验证 · ADR-11）
- **结构化判定**：单品 `discountType ∈ {麦金卡优惠, 随单购麦金卡优惠}`（辅助信号：分类名 `麦金卡专享`）。
- **以单品字段为准**：跨分类 SKU（如 `9900000002` 落在"人气热卖"但 `discountType=="麦金卡优惠"`）必须靠单品字段识别，否则漏判。
- `tags[]` 为自由文本，**不作**判定依据。
- **路径 A 可直接试算**（H2 部分成立）：下单卡专享 SKU 即自动出 `discount`（无需传卡 code）；**普通商品不自动套卡**。报告须标注"省额来自卡专享 SKU 价差"。**无独立卡来源字段**。

## 持卡判定（H4 已验证不成立）
- `query-my-account` 无卡状态字段；全工具清单无卡状态工具。
- 采用"**用户自述** + **运行时推断**"：① 明确询问是否持卡；② 若在卡专享 SKU 上试算出低于普通价的价格 → 推定权益可用。
- **禁止**宣称"已确认您持有麦金卡"。

## 失败分支
- 识别到员工卡等身份折扣（与麦金卡不叠加）→ 🔴RL-17：「无法判断两条路径相对优劣」，**不给数字**。
- 权益门店适用范围差异（H6）→ 按 `storeCode` 校验，非适用门店不报卡价。
- 卡专享价因果未验证（无对照 token）→ 报告如实声明"无法排除该价对所有人公开"。

## 结构改造（P1-1）
- 未达门槛 → 给"凑 X 元到 Y 门槛可省 Z 元"方案（`calculate-price` 真实试算）；**"不划算就不建议凑"**。
