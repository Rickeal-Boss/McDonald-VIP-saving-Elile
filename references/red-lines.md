## RL-23 的判定与降级（`scripts/identity_guard.py`）

`calculate-price` 响应的 `data.enjoyed` **语义双关**，必须先分类再决定能否计数：

| `enjoyed` 形态 | 判定 | 处置 |
|---|---|---|
| 券 / 活动（`promotionName` 含「券 / coupon / promo / 立减 / 满减」等） | `conflict=False` | **按券省额计入**（通道保留） |
| 身份折扣（含「员工卡 / 员工餐 / 内部 / 家属卡 / 亲情卡 / staff / employee / identity」等，或 `type` 指向身份类） | `conflict=True` | **恒不计入**券省额；路径标 `identity_conflict` + `saving_incomplete`；**不给省额数字**；报告走 RL-23 话术且**不下优劣结论** |
| 券/身份词**同时**命中 | 保守按**身份折扣** | 同上行（少报 > 虚报） |
| 无任何名称/类型字段可辨 | `indeterminate=True` | 按券通道计入**并**留「待复核」痕（Trace + 报告 note） |

⚠️ **诚实边界**：测试账号真机三次试算 `enjoyed` **恒缺省**，本规则**无测试账号真机样本**，
依据为外部调研（大赛 #60「麦回本 mc-breakeven」实测）+ 字段语义推断 → 记入
`references/assumptions.md` **H8【待验证假设】**，**严禁**当已验证事实宣传。

## RL-01 的执行层级与诚实定位（**勿夸大**）

《只读》这条红线由**三层**共同保障，各层强度不同，必须如实区分：

| 层级 | 载体 | 强度 | 说明 |
|---|---|---|---|
| **L-a 规则层（真正的强制）** | `SKILL.md` 硬规则（RL-01，启动即加载） | 强 | Agent 的行为约束；不调用写操作是技能成立前提 |
| **L-b 平台层（如适用）** | 平台 Hook / 连接器权限 | 强（平台相关） | 在 MCP 通道出入口拦截写工具（若平台支持，应在此层封死） |
| **L-c 脚本层（辅助）** | `scripts/whitelist.py` | **弱（辅助）** | 「调用前策略辅助 + 违规检测」：在**技能自身脚本链路内**前置守卫，写操作在数据层被拒；并对越权调用留痕（Trace `redline`） |

**关键诚实声明**：
> `whitelist.py` **不是架构级强制拦截** —— 技能脚本运行在 Agent 之外，
> **无法拦截 Agent 直接发起的 MCP 工具调用**。因此：
> **严禁**在文档 / 报告 / 宣传中宣称「脚本已封死写操作」。
> 宁可如实降级声明：脚本层做辅助守卫与检测，真正的只读强制依赖 L-a（+ 适用时的 L-b）。
